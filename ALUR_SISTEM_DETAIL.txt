# ALUR SISTEM POS APOTEK SUMBER WARAS — DETAIL LENGKAP

================================================================================
                             ARSITEKTUR SISTEM
================================================================================

Frontend   : Next.js 14 (App Router) + TypeScript + Tailwind CSS
Backend    : Express.js 4 (Node.js) + mysql2/promise
Database   : MySQL 8+
Auth       : JWT (jsonwebtoken) + bcryptjs, dual-layer (cookie middleware + client)
Payment    : Midtrans Snap (sandbox)
Forecast   : Google Gemini API + Holt-Winters + OpenRouter
File Upload: Multer (memoryStorage → LONGBLOB MySQL)
Notifikasi : goey-toast
Icons      : lucide-react

Struktur Provider:
<html>
  <head><Script src="https://app.sandbox.midtrans.com/snap/snap.js" ... /></head>
  <body>
    <OffCanvasProvider>
      <AuthProvider>
        <HeaderProvider>
          <SidebarProvider>
            <KeyboardShortcutsProvider>
              <MainLayout>
                {children}  ← halaman yang diakses
              </MainLayout>
            </KeyboardShortcutsProvider>
          </SidebarProvider>
        </HeaderProvider>
        <GoeyToaster />
      </AuthProvider>

================================================================================
                     ALUR 1: AUTHENTIKASI & LOGIN
================================================================================

1. User akses halaman manapun (selain /login, /register, /forgot-password)

2. Next.js Middleware (src/middleware.ts):
   a. Baca cookie 'token'
   b. Jika tidak ada → redirect ke /login
   c. Jika ada → lanjut

3. Client-side AuthProvider (src/components/AuthProvider.tsx):
   a. Cek localStorage.getItem('token')
   b. Jika tidak ada → redirect ke /login
   c. Jika ada → render children

4. Halaman Login (src/app/login/page.tsx):
   a. Form: username, password
   b. Klik "Login"
   c. Fetch POST http://localhost:5000/api/auth/login
      - Body: { username, password }
   d. Backend:
      - Cari user di tabel users WHERE username = ? AND status = 'active'
      - Jika tidak ditemukan → 401
      - Compare password dengan bcrypt
      - Jika salah → 401
      - Jika benar:
        * Generate JWT: jwt.sign({ id: user.id, username, role }, SECRET, { expiresIn: '24h' })
        * Return 200: { token, user: { id, username, role, full_name } }
   e. Frontend:
      - Simpan token di localStorage
      - Simpan user (JSON) di localStorage
      - Set cookie 'token' = token
      - Dispatch event 'auth:changed' di window
      - Redirect ke /dashboard

5. Auto-logout (terjadi ketika):
   - API return 401 → localStorage.clear() + cookie dihapus + redirect /login
   - Token expired → middleware redirect ke /login


================================================================================
                ALUR 1b: REGISTER & FORGOT PASSWORD
================================================================================

--- REGISTER ---
1. Akses /register
2. Isi form: username, password (min 6), konfirmasi password
3. Submit → POST http://localhost:5000/api/auth/register
4. Backend:
   - Cek username unik
   - Hash password dengan bcrypt
   - INSERT ke tabel users, role default 'kasir', status 'active'
   - Return 201 { message, id }

--- FORGOT PASSWORD (4 Langkah) ---
Langkah 1: Kirim Email
   a. Akses /forgot-password, masukkan email
   b. POST /api/forgot-password → { email }
   c. Backend:
      - Generate 6-digit random code
      - Simpan di password_reset_requests (email, code hash, expires_at + 15 menit)
      - Kirim email via nodemailer (Gmail SMTP)
      - Return 200 { message }
   d. Frontend → lanjut step 2

Langkah 2: Verifikasi Kode
   a. Masukkan kode 6-digit
   b. POST /api/verify-reset-code → { email, code }
   c. Backend:
      - Cari record di password_reset_requests WHERE email AND code AND expires_at > NOW()
      - Jika cocok → set verified = true, return 200
      - Jika tidak → 400
   d. Frontend → lanjut step 3

Langkah 3: Reset Password
   a. Masukkan password baru + konfirmasi
   b. POST /api/reset-password → { email, code, new_password }
   c. Backend:
      - Verifikasi code & verified = true & belum used
      - Hash password baru
      - UPDATE users SET password = ?
      - Tandai request sebagai used
      - Return 200
   d. Frontend → lanjut step 4 (Done, link ke /login)

   k. Tanggal Kadaluarsa (expired_date — default)
   l. Gambar (upload via file)

6. Backend (routes/products.js):

================================================================================
              ALUR 4: MANAJEMEN FAKTUR / BATCH (DALAM PRODUCTS)
================================================================================

--- 4a. Melihat Faktur Suatu Produk ---
1. Di halaman Products, klik baris produk → buka Faktur OffCanvas (lebar 800px)
2. State: isFakturOffCanvasOpen = true
3. Fetch GET /api/inventory/batches/:productId
   - Backend: SELECT batches JOIN suppliers, JOIN batch_dp_payments
4. Tabel: nomor batch, supplier, tipe stok, tgl beli, qty awal, sisa stok,
   harga, status (Disetujui/Menunggu/Ditolak/Revisi)
5. Status badge warna: approved=green, pending=yellow, rejected=red, revision=orange

--- 4b. Menambah Faktur Baru ---
1. Dalam Faktur OffCanvas, klik "Tambah Faktur"
2. State: showFakturForm = true, fakturModalMode = 'add'
3. Form muncul di dalam OffCanvas (inline, bukan modal terpisah)
4. Field:
   a. Nomor Batch/Invoice (opsional)
   b. Supplier (dropdown)
   c. Tipe Stok:
      - Belum Bayar (hutang)
      - Konsinyasi (titip jual)
      - DP (bayar sebagian)
      - Lunas (bayar lunas)
   d. Tanggal Pembelian
   e. Unit Pembelian (Box/Strip/Botol/Tube/Pcs)
   f. Unit Dasar (Tablet/Kapsul/dll)
   g. Isi Per Unit (unit_multiplier — konversi)
   h. Jumlah (dalam unit pembelian)
   i. Harga Beli per unit dasar
   j. Harga Jual per unit dasar
   k. Tanggal Kadaluarsa (untuk batch ini)
   l. Jika tipe DP:
      - Jumlah DP (IDR) — otomatis jadi DP 1
      - Tanggal Jatuh Tempo
   m. Catatan
   n. Upload Bukti Faktur (file atau kamera)
5. Klik "Tambah Faktur"
6. Frontend (handleSaveFaktur):
   a. Update dulu data produk: PUT /api/products/:id
      (harga beli, harga jual, unit, purchase_unit, unit_multiplier, supplier_id)
   b. Kirim batch: POST /api/inventory/batches (FormData: image + fields)
7. Backend (routes/inventory.js POST):
   a. Hitung qtyInBaseUnit = quantity × unit_multiplier
   b. Hitung totalAmount = qtyInBaseUnit × cost_price
   c. Cek approval:
      - Jika totalAmount > 2.000.000 → status = 'pending'
      - Jika ≤ 2.000.000 → status = 'approved'
   d. INSERT batch
   e. Jika tipe DP dan dp_amount diisi:
      - Auto-create batch_dp_payments (DP 1):
        INSERT INTO batch_dp_payments (batch_id, amount, payment_date, 'cash')
   f. Jika status = 'approved':
      - UPDATE products SET stock = stock + initial_quantity
      - Buat jurnal akuntansi:
        * Debit Persediaan (110) = totalAmount
        * Jika Lunas: Credit Kas (101) = totalAmount
        * Jika DP: Credit Kas (101) = dp_amount, Credit Hutang (201) = sisa
        * Jika Belum Bayar/Konsinyasi: Credit Hutang (201) = totalAmount
   g. Audit trail
   h. Return { success, data: { id, status } }
8. Frontend:
   - Jika status = 'pending' → toast "Persetujuan Diperlukan"
   - Jika status = 'approved' → toast sukses
   - Reset form, refresh faktur list, refresh produk

--- 4c. Edit Faktur ---
1. Klik edit pada faktur → form terbuka dengan data existing
2. Ubah field, klik "Simpan Faktur"
3. PUT /api/inventory/batches/:id
4. Backend:
   a. Ambil batch lama (remaining_quantity, status, product_id)
   b. Hitung ulang totalAmount → re-evaluasi approval
   c. UPDATE batches
   d. Handle stock changes:
      - Jika oldStatus=approved & newStatus=approved:
        stock += (newRemaining - oldRemaining)
      - Jika oldStatus≠approved & newStatus=approved:
        stock += newRemaining
      - Jika oldStatus=approved & newStatus≠approved:
        stock -= oldRemaining
   e. Handle jurnal ulang jika perlu
   f. Audit trail

--- 4d. Hapus Faktur ---
1. Klik ikon hapus → ConfirmModal
2. DELETE /api/inventory/batches/:id
3. Backend: HAPUS batch (cascade ke batch_dp_payments) + audit trail

--- 4e. Manajemen DP ---
1. Di Ringkasan Pembayaran (hanya muncul di mode edit & tipe DP):
   a. Total Faktur (cost_price × initial_quantity)
   b. Daftar DP yang sudah dibayar:
      - DP 1: RpXXX (tanggal) [Cash/TF] [tombol hapus]
      - DP 2: RpXXX (tanggal) [Cash/TF] [tombol hapus]
   c. Total DP
   d. Sisa Hutang (atau Lunas jika sudah lunas)
2. Tambah DP:
   a. Klik "Tambah DP"
   b. Form: Jumlah DP, Tanggal Bayar, Metode Pembayaran (Cash / Transfer)
   c. Klik "Simpan DP"
   d. POST /api/inventory/batches/:batchId/dp-payments
      - Body: { amount, payment_date, payment_method }
   e. Backend: INSERT batch_dp_payments + audit trail
   f. Refresh faktur list
3. Hapus DP:
   a. Klik ikon hapus → ConfirmModal "Yakin ingin menghapus DP RpXXX?"
   b. DELETE /api/inventory/batches/:batchId/dp-payments/:paymentId
   c. Backend: DELETE + audit trail

--- 4f. Arsipkan Faktur ---
1. Klik "Arsipkan" (hanya muncul jika stock_type = 'lunas')
2. Konfirmasi
3. PUT /api/inventory/batches/:id/archive → { is_archived: true }
4. Backend: cek stock_type = 'lunas', lalu UPDATE is_archived = 1
5. Jika tidak lunas → return 400 "Hanya faktur dengan tipe stok lunas..."

--- 4g. Upload Bukti Faktur ---
1. Pilih file dari galeri atau ambil foto via kamera (capture="environment")
2. Preview image muncul
3. Dikirim sebagai FormData bersama data batch lainnya

================================================================================
            ALUR 7: TRANSAKSI PENJUALAN (POS) — DENGAN FEFO!
================================================================================

--- 7a. Persiapan Transaksi ---
1. Akses /transactions
2. State:
   - cart: array of { product, batchId, quantity, sellingPrice, costPrice }
   - paymentMethod: 'cash' | 'midtrans'
   - amountTendered, discount, ppnRate

--- 7b. Memilih Produk ---
1. Search produk (by nama atau kode)
2. Klik produk → tambah ke cart
3. Atur jumlah (qty)
4. Jika stok tidak cukup → error toast
5. Lihat subtotal, diskon, PPN, total

--- 7c. FEFO (First Expired First Out) — Backend ---
1. POST /api/transactions
2. Backend (routes/transactions.js):
   a. Validasi: stock_type harus 'OBAT' punya batch, total qty > 0
   b. Untuk setiap produk:
      i. Query: SELECT * FROM batches WHERE product_id = ?
         AND remaining_quantity > 0 AND is_archived = FALSE
         ORDER BY expired_date ASC, created_at ASC
      ii. Loop batch (FEFO):
          - Ambil dari batch dengan expired_date TERKECIL (paling cepat kadaluarsa)
          - Jika batch tidak cukup, lanjut ke batch berikutnya
          - Contoh: butuh 10 pcs
            Batch A (exp 2026-06-10, sisa 4) → ambil 4, sisa butuh 6
            Batch B (exp 2026-06-15, sisa 8) → ambil 6, sisa butuh 0
      iii. Simpan transaksi_items per batch
   c. Insert header transaksi
   d. Update remaining_quantity tiap batch
   e. Update stock produk (total)
   f. Buat jurnal:
      - D: Kas (101) / Piutang Midtrans ( jika midtrans )
      - C: Penjualan OBAT ( jika produk kategori OBAT )
      - C: Penjualan NON_OBAT ( jika produk kategori NON_OBAT )
      - C: PPN Keluaran ( jika ada PPN )
      - D: HPP OBAT (cost_price untuk produk OBAT)
      - C: Persediaan OBAT (cost_price untuk produk OBAT)
      - D: HPP NON_OBAT (cost_price untuk produk NON_OBAT)
      - C: Persediaan NON_OBAT (cost_price untuk produk NON_OBAT)

--- 7d. Pembayaran Tunai ---
1. Input jumlah dibayar
2. Hitung kembalian
3. Klik "Bayar"
4. POST /api/transactions dengan payment_method = 'cash'
5. Backend: langsung complete + jurnal
6. Tampilkan struk (modal receipt)

--- 7e. Pembayaran Midtrans ---
1. Pilih metode: Kartu Kredit / Debit / QRIS
2. POST /api/transactions dengan payment_method = 'midtrans'
3. Backend:
   a. Insert transaksi (payment_status = 'pending')
   b. Panggil Midtrans Snap API → dapatkan redirect_url + token
   c. Return { snap_token, ... }
4. Frontend: snap.pay(snap_token, ...)
5. User bayar di popup Midtrans
6. Callback dari Midtrans → POST /api/midtrans/notification
7. Backend update payment_status = 'settlement'/'capture'
8. Frontend polling atau callback → tampilkan struk

--- 7f. Cetak Struk ---
1. Modal receipt muncul
2. Info: nama apotek, tgl, item, total, bayar, kembalian
3. Klik "Cetak" → window.print()

================================================================================
                        CATATAN PENTING
================================================================================

1. FEFO: Stok batch dengan expired_date paling awal harus dijual duluan.
   Query: ORDER BY expired_date ASC, created_at ASC.
   Jangan cuma update total stock produk — harus kelola remaining_quantity
   per batch!

2. Approval: Faktur dengan total > Rp2.000.000 otomatis pending.
   Approver harus approve dulu sebelum stok masuk.

3. DP Payment: Auto-create "DP 1" saat create faktur dengan tipe dp + dp_amount.
   DP berikutnya ditambahkan manual via "Tambah DP" di Ringkasan Pembayaran.

4. Arsip: Hanya faktur dengan tipe 'lunas' bisa diarsipkan.

5. Superadmin: Bypass permission cuma berlaku jika record permission TIDAK ADA.
   Jika record ada dengan allowed=0, superadmin pun ditolak.

6. Jurnal Akuntansi:
   - Pembelian: D Persediaan, K Kas/Hutang (tergantung tipe)
   - Penjualan: D Kas, K Penjualan + PPN, D HPP, K Persediaan
   - Transaksi Keuangan (manual): via Transaksi Keuangan wizard
